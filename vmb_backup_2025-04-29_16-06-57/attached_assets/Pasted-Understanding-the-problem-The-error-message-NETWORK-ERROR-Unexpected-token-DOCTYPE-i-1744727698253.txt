Understanding the problem
The error message [NETWORK ERROR] Unexpected token '<', "<!DOCTYPE "... is not valid JSON indicates that a network request expected a JSON response but received HTML instead. This usually happens when the server responds with an HTML page (often an error page like a 404 or 500) instead of the expected JSON data. The browser tries to parse the HTML as JSON, encounters the < character at the beginning of the HTML document, and throws an error because it's not valid JSON syntax. The stack trace Mt.forEach.n.<computed> @ Console.js:61 points to where the error was encountered while processing the response, likely within your console overriding logic.

How to verify
Identify the failing request: Use the Network tab in Chrome DevTools to find the request that triggered the error. Look for requests that have failed or have an HTML response when JSON was expected.
Examine the response: Inspect the response content of the failing request in the Network tab. You should see HTML content instead of JSON.
Check the server logs: If you have access to the server-side logs, check them for errors or issues related to the failing request. This can help pinpoint why the server is returning HTML instead of JSON.
Suggested fix
The core issue is that your application is expecting a JSON response from a particular network request, but the server is returning HTML, likely due to an error or misconfiguration on the server-side. You need to debug why the server isn't returning JSON for that specific request. Here's a general approach, but the exact fix depends on your server-side implementation:

Server-side debugging: Identify the route or endpoint associated with the failing request. Check for errors in your server-side code, database issues, or incorrect configurations that might lead to the server returning an HTML error page instead of the expected JSON. Ensure the server is setting the Content-Type header to application/json in the response when it intends to return JSON.
Client-side error handling: Improve your client-side error handling to gracefully handle cases where the server returns an unexpected response. Instead of assuming every response is valid JSON, check the response status code and content type before attempting to parse it as JSON. For example:
