1. Baseline Rule Enforcement Strategies (Automated + Structural)
✅ A. Write Unit + Integration Tests for Each Rule
Each core rule (e.g., sponsor-client relationship, unique invitation ID, access control) should have at least one test that fails if the rule is broken.

Example: If a client is registered without a sponsor, test should fail and show an error like Missing sponsor relationship.

Sample (in Jest / Playwright / whatever you're using):
ts
Copy
Edit
test('client must have a sponsor', async () => {
  const result = await registerClient({ name: "Test", sponsorId: null });
  expect(result.error).toBe("Sponsor relationship is required");
});
✅ B. Static Checks & Lint Rules
Create a custom linting rule or script that checks for:

Disallowed terms like handlePayment

Unused imports or deprecated naming conventions

Bad formatting of phone numbers

Use eslint-plugin or custom Prettier rules to ensure formatting like (xxx) xxx-xxxx.

✅ C. Schema Validation / ORM Constraints
Use tools like Zod, Yup, or Prisma schema validation to enforce business rules at model level.

Enforce foreign key constraints and uniqueness at DB level too.

⚙️ 2. Code-Level Safeguards (Locking + Comments + Contracts)
✅ A. “Do Not Modify” Comment Tags
In files with finalized logic (e.g., clientRegistration.ts), place:

ts
Copy
Edit
// === VMB RULE ENFORCEMENT BLOCK: DO NOT MODIFY WITHOUT LEAD APPROVAL ===
// Enforces: sponsor-client link, fallback to VMB LTD, phone format standard
✅ B. Use “Guard Clauses” or Contracts
Functions like registerClient() should have early fails for any rule violation:

ts
Copy
Edit
if (!input.sponsorId) throw new Error("Every client must have a sponsor. Default is VMB LTD.");
🚦 3. CI/CD Enforcement (Preflight + Gatekeeping)
✅ A. Pre-Commit / Pre-Push Hooks
Use husky + lint-staged + prettier to:

Block code that violates naming standards or includes restricted terms

Run only changed file tests before committing

✅ B. Automated Pull Request Checks
Configure your CI pipeline to:

Run test suite + schema checks

Reject PRs missing required rule validation or that weaken access logic

🗂️ 4. Code Documentation + Rule Manifest in Repo
✅ A. Add a /RULES.md or /docs/baseline.md file
This should list:

The foundational platform rules

Their corresponding test files or modules

Who owns or maintains them

✅ B. Tag Each Rule in Code Comments
E.g.:

ts
Copy
Edit
// [RULE: UniqueInvitationID] -- enforced via validateInvitationCode() in utils.ts
🛡️ 5. Immutable Logic Strategy
For key rules like sponsor assignment or invitation ID:

Use factory functions or services with frozen logic (e.g. Object.freeze)

Prevent override or mutation of critical values (e.g., invitation ID)

ts
Copy
Edit
Object.freeze(invitation); // prevents downstream mutation
🔍 6. Monitor for Violations Over Time
✅ A. Add Logs for Rule Violations
Whenever fallback logic is triggered or a rule is skirted, log:

ts
Copy
Edit
logger.warn(`Default sponsor used: client ${clientId} assigned to VMB LTD`);
✅ B. Audit Reports / Rule Compliance Scans
Periodically run scripts to scan DB for rule anomalies:

Clients without sponsors

Duplicate phone numbers

Invitations without a recipient
